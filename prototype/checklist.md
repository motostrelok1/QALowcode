## Ключевые находки

1. **Текст и Enter — только через `execCommand`** (`insertText` / `insertParagraph`). Синтетические `keydown` редактор игнорирует. П. 7.2c спеки переписан соответственно.
2. **Меню в «Яге» многоуровневое и мышечно-ориентированное:**
   - пункты со стрелкой «›» — это **папки-подменю**: клик по ним открывает следующий уровень, а не применяет действие. Цепочка «Таблица» = меню → подменю («Статическая/Динамическая») → **сетка выбора размера** → клик по ячейке. Три уровня вложенности — прямое подтверждение дизайна цепочек п. 6.3.
   - **Enter/стрелки в меню не работают даже для живого пользователя** (проверено вручную) — только ЛКМ. Значит клавиатурный путь воспроизведения не нужен вовсе.
   - **Синтетические клики (`el.click()`, dispatchEvent Mouse/Pointer) пункты меню игнорируют.** Работает только trusted-ввод: CDP `Input.dispatchMouseEvent`. Для расширения это означает `chrome.debugger` (см. следствие 4).
3. **Ловушка интерпретации:** «клик не сработал» и «клик открыл подменю» снаружи выглядят одинаково. Проверку результата действия делать по ожидаемому следствию (появление подменю/блока), а не по одному признаку.
4. **Следствие для архитектуры воспроизведения (п. 7.2c):** два канала ввода —
   - текст/абзацы: `execCommand` из content script (без баннера);
   - меню и прочие упрямые контролы: `chrome.debugger` CDP (баннер «расширение отлаживает браузер»). Включать `chrome.debugger` точечно на время прогона и отключать сразу после — UX-риск зафиксировать в спеке; кандидат на смягчение: разрешение `debugger` запрашивать как optional.
5. **Кандидат на проверку позже:** CDP `Input.insertText` (trusted-ввод текста) — может заменить execCommand там, где execCommand не сработает.
