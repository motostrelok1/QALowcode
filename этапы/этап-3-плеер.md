# Этап 3 — Плеер: воспроизведение кликов и ввода

**Статус:** ждёт этапы 1–2 **Покрывает:** п. 7.2 (a–d), 7.3, 7.4, 6.5 спецификации (базовая часть)

## Цель

Последовательное воспроизведение записанного теста: резолв элементов с единым таймаутом шага, выполнение кликов и ввода в обычные поля, обработка провалов, лог прогона.

## Входит

1. **Запись ввода (дополняет этап 1):** слушатели `input`/`change` для обычных полей (`input`, `textarea`, `select`), накопление до паузы ~800 мс или завершающего события, шаг `action: "input"` с `value`. (Contenteditable — этап 5c.)
2. **Резолв (п. 7.2b):** единый `wait_timeout_ms` на шаг; опрос всех кандидатов каждые 100 мс в порядке приоритета; первый найденный — победил; текстовые кандидаты пробуются сначала `raw`, потом `normalized`; учёт `within`.
3. **Действия:**
   - `click`: `mousedown` → `mouseup` → `click` на целевом элементе;
   - `input` (обычные поля): установка `value` + события `input`/`change`; если поле игнорирует прямую установку (React controlled input) — посимвольная эмуляция через нативный сеттер (`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set`);
   - `wait`: ожидание таймаута;
   - `assert`: сравнение `textContent` (normalized) с эталоном + кнопка «Отметить проверку» в панели (п. 6.7).
4. **Обработка провала (п. 7.4):** настройка на тест — Stop / Skip / Soft fail; провал шага = общий таймаут истёк, все кандидаты 🔴.
5. **Лог (п. 7.3):** на шаг — сработавший кандидат, время резолва, результат; пометки 🟢/🔴 улетают в карточку шага (этап 2).
6. **Кнопка «Запустить только этот шаг»** в карточке.
7. **Автотайминги при записи (п. 6.5):** фиксация `recorded_response_time_ms`, предложение `wait_timeout_ms` = ×5–10.
8. **Итоговая сводка** (пройдено/всего, время) — текстом в панели; красивый вид — этап 5d.

## Не входит

- Кэш тегов `data-qa-id`, фазы ⚡/🔄⚠️ — этап 5d (на этом этапе каждый шаг резолвится заново, `resolution` всегда `resolve`).
- Цепочки, проверка целостности контейнера (п. 7.2e) — этап 5b.
- Contenteditable — этап 5c.
- Навигация между страницами (состояние прогона в background) — после спеки 0.3.

## Критерии приёмки

1. Записанный сценарий из 5–10 шагов (клики + ввод в форму) воспроизводится начисто на свежей вкладке.
2. Шаг с «медленным» элементом (появляется через 1–2 с) проходит за счёт опроса до таймаута, не флаки.
3. Удаление элемента со страницы → шаг 🔴, срабатывает выбранная стратегия (Stop/Skip/Soft fail).
4. React-форма (controlled inputs) заполняется, сабмит видит значения.
5. `assert` с нормализацией ловит расхождение текста, но не падает на `\u00a0`/двойных пробелах.
6. Время прогона и лог по шагам видны в панели.

## Риски

- SPA перерисовывает элемент между резолвом и кликом (stale reference) → перед действием проверять `element.isConnected`, при потере — повторный резолв в остаток таймаута.
- React controlled input — неизбежен спец-путь с нативным сеттером; вынести в отдельную функцию с тестом на реальном приложении.
