# Этап 1 — Content script: запись кликов и сбор кандидатов

**Статус:** ждёт этап 0 **Покрывает:** п. 6.1, 6.2, 4, 4.1, 4.2 основной спецификации (частично)

## Цель

Content script на странице записывает клики тестировщика и для каждого события строит полный список кандидатов-селекторов с проверкой уникальности. Шаги уходят в Side Panel (этап 2).

## Входит

1. **Слушатель** `click` (+ `mousedown` для будущих скриншотов) на `document` в capture-фазе; игнорирование кликов по UI самого расширения.
2. **Подъём к интерактивному элементу:** от `event.target` вверх к ближайшему `button` / `a` / `[role=button]` / `[onclick]` / `input` / `select` / `[tabindex]`.
3. **Генераторы кандидатов** по приоритетам 1–3, 5–7 (приоритет 4 — тултипы — этап 5a):
   - `data-testid` / `data-qa`;
   - `id` — с отсечкой генерируемых (эвристика: ≥4 цифр подряд, хэш-подобные строки, префиксы вида `:r1:` React, `ember`, `mui-`);
   - `name`;
   - видимый текст — с хранением `raw` + `normalized` (п. 4.2);
   - классы + тег (стабильные классы: отсекаем хэш-суффиксы CSS-modules вида `.btn_a3f9c`);
   - относительный CSS/XPath от ближайшего «якорного» предка — крайний fallback.
4. **Проверка уникальности** каждого кандидата на странице; при неоднозначности — базовая достройка `within` (ближайший семантический контейнер: `tr`, `li`, `[role=listitem]`, `article`, `section` + текстовый якорь внутри него, п. 4.1).
5. **Транспорт:** отправка шага в Side Panel через `chrome.runtime` messaging; буферизация, если панель закрыта.
6. **Каркас расширения:** `manifest.json` (MV3), регистрация content script, минимальный background SW (пока только ретранслятор).

## Не входит

- Запись ввода в поля (`input`/`change`) — этап 3 (вместе с плеером, чтобы было что проверять).
- Тултип-атрибуты (приоритет 4) — этап 5a.
- Цепочки меню, `group_id`, MutationObserver — этап 5b.
- Contenteditable — этап 5c.
- Скриншоты — этап 5e.
- Навигация между страницами — после ответа на вопрос 3 этапа 0 (кандидат в спеку 0.3).

## Критерии приёмки

1. Клик по кнопке с `data-testid` → шаг с кандидатом приоритета 1 первым в списке.
2. Клик по кнопке без testid, но со стабильным текстом → текстовый кандидат (raw + normalized), уникальность подтверждена.
3. Клик по кнопке «Удалить» в одной из одинаковых строк таблицы → кандидат не принят как неуникальный, построен `within` с текстовым якорем строки.
4. Клик по иконке `<svg>` внутри кнопки → шаг ссылается на кнопку, не на svg.
5. Элемент с генерируемым `id` (`:r3:`, `mui-4832`) → id-кандидат отсутствует или помечен как отсеянный.
6. Все шаги видны в панели (интеграция с этапом 2) и сериализуются в JSON по схеме п. 3.

## Риски

- Эвристика «генерируемый id» даст ложные срабатывания → логировать отсеянные кандидаты для ручной проверки.
- CSS-modules классы: эвристика стабильности классов — кандидат в ручную настройку на первых реальных тестах.
