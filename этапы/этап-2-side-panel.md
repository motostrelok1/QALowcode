# Этап 2 — Side Panel: список шагов и карточка

**Статус:** ждёт этап 1 (источник данных) **Покрывает:** п. 8.1, 8.3 (базовая часть) спецификации

## Цель

UI редактора в Side Panel: тестировщик видит записанные шаги, правит описания и тайминги, управляет записью.

## Входит

1. **Шапка:** имя теста (редактируемое), кнопки «Запись» / «Стоп», «Пауза записи» (п. 6.7), счётчик шагов.
2. **Список шагов (слева):** компактные строки — номер, иконка `action`, `human_label`; выбор строки открывает карточку; удаление шага; перетаскивание (перенумерация `order` с шагом 10).
3. **Карточка шага (справа), базовая:**
   - иконка действия + редактируемое `human_label`;
   - `resolution` (resolve / by_tag) — отображается, не редактируется;
   - список кандидатов с пометками ⚪ (пометки 🟢/🔴 появятся с плеером — этап 3);
   - поля `wait_timeout_ms`, `post_action_delay_ms` — числовые инпуты;
   - текстовое поле `value` для шагов ввода.
4. **Каркас панели:** HTML/JS без фреймворка (vanilla + один CSS), чтение шагов через messaging от content script, хранение черновика теста в памяти до этапа 4.

## Не входит

- Скриншоты и миниатюры — этап 5e.
- Сводка прогона (п. 8.5) и индикация фаз (п. 8.2) — этап 5d.
- Группировка по `group_id` (п. 8.4) — этап 5b.
- «Обновить селектор» (перевыбор элемента на странице) — этап 5d (нужен кэш-теговый контур).
- «Запустить только этот шаг» — этап 3.
- Кнопка «Отметить проверку» (assert) — этап 3 (нужен плеер для проверки).

## Критерии приёмки

1. Записанные на этапе 1 шаги появляются в списке в реальном времени.
2. Правка `human_label` и таймингов сохраняется в модели теста и выгружается в JSON.
3. Перетаскивание шага меняет порядок, `order` пересчитывается (10, 20, 30…).
4. Панель не ломается при закрытии/открытии во время записи (буферизация на стороне content script / background).

## Риски

- Side Panel не имеет доступа к DOM страницы — вся работа только через messaging; заложить тонкий слой-протокол сообщений с самого начала (он переиспользуется плеером).
