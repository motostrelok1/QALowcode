# Этап 5e — Скриншоты шагов

**Статус:** ждёт этапы 2–4 **Покрывает:** п. 6.6, 7.3 (часть про «сейчас» vs «при записи»), 8.3 (миниатюра) спецификации

## Цель

Визуальное превью элемента в карточке шага и кадр «сейчас» при прогоне для сравнения.

## Входит

1. **Запись (п. 6.6):** на `mousedown` — `getBoundingClientRect()` элемента → запрос в background → `chrome.tabs.captureVisibleTab` → обрезка по координатам (с отступом ~8 px, клэмп по краям) → blob в `screenshots` (IndexedDB, этап 4), ссылка в шаге.
2. **Лимит API:** ~2 вызова `captureVisibleTab` в секунду — очередь с дросселированием; пропуск кадра допустим (шаг остаётся без скриншота, не блокирует запись).
3. **Прогон (п. 7.3):** опциональный кадр «сейчас» для проваленных и ре-резолвленных шагов — тот же конвейер.
4. **UI:** миниатюра в карточке шага; клик — полный размер; при наличии обоих кадров — просмотр «при записи / сейчас» рядом.

## Не входит

- Пиксельное сравнение (визуальная регрессия) — вне зоны v0.1 (п. 1.1).
- Скриншот всей страницы / скролл-кадры.

## Критерии приёмки

1. У записанного шага есть миниатюра с правильным элементом в кадре.
2. Быстрая запись подряд (5 кликов за секунду) не роняет запись: часть кадров пропущена, шаги целы.
3. Кадры лежат в IndexedDB и переживают перезапуск; при экспорте JSON скриншоты не раздувают файл (экспорт без blob, или отдельной опцией — решить в реализации).
4. Проваленный шаг при прогоне получает кадр «сейчас», в карточке видны оба.

## Риски

- `captureVisibleTab` требует активную вкладку и разрешение `activeTab`/`<all_urls>` → зафиксировать в манифесте и в инструкции по установке.
- HiDPI: координаты `getBoundingClientRect` в CSS-пикселях, кадр — в физических → учесть `devicePixelRatio` при обрезке.
