# Этап 5a — Тултипы как кандидаты (приоритет 4)

**Статус:** ждёт этапы 1–3 **Покрывает:** раздел 5 спецификации

## Цель

Добавить в генератор кандидатов четвёртый приоритет: `aria-label`, `title`, тултип-атрибуты JS-библиотек — с триггера, не из портала.

## Входит

1. **Кандидаты:** `[aria-label="..."]`, `[title="..."]`, `[data-tippy-content="..."]`, `[data-tooltip]`, `[data-popper-*]`-конфиги — список атрибутов расширяемый (конфиг в одном месте).
2. **Только с триггера:** чтение атрибута-конфига на самом элементе; содержимое всплывающего портала в `<body>` для идентификации не используется.
3. **Позиция в иерархии:** между `name` (3) и видимым текстом (5) — пересборка кандидатов для существующих шагов не требуется, действует на новые записи.
4. **Шаг `assert` для самого тултипа (п. 5):** ручной шаг «проверить текст тултипа» — наведение (`mouseenter`/`mouseover`) → ожидание появления портала до таймаута → сравнение текста. Это использование портала для *проверки*, не для идентификации.

## Не входит

- Автоопределение библиотеки тултипов сверх списка атрибутов.
- Hover-шаги в записи (события `mouseenter` пишутся только как часть assert-тултипа, иначе — шум).

## Критерии приёмки

1. Кнопка-иконка с `aria-label` → кандидат приоритета 4 выше текстового.
2. Элемент с `data-tippy-content` → кандидат строится по атрибуту триггера, без ожидания появления портала.
3. Assert-тултип проходит на совпадающем тексте и падает на изменённом.
4. Элемент без тултип-атрибутов → список кандидатов не изменился относительно этапа 1.

## Риски

- Локализация: тексты тултипов меняются как и видимый текст → та же нормализация (п. 4.2), то же место в иерархии (ниже структурных признаков).
